# 快速上手：把一个内网服务发布到外网

从零开始，把家里的一个服务（这里拿 NAS 的 DSM 举例）变成在外面能打开的地址。

全程在管理后台点，不用改配置文件。看着长是因为把每一步为什么这么做也写了，实际操作大概十分钟。

**这篇假设你有一个域名。** 没有域名也能用，只是外面访问时要记 `IP:端口` 这种地址，而端口是会变的——到[第 4 步](#4-让地址固定下来)会说明。

---

## 0. 先确认你的网络能不能打洞

LinkStar 靠打洞工作，而打不打得通取决于运营商给你的 NAT 类型。**这一步花一分钟，能省掉后面所有的白折腾。**

装好启动，进 `http://localhost:3333/linkstar/`，看「内网穿透」页面上方：

- **公网 IP** 有值 —— STUN 探测正常。
- **NAT 类型**：
  - `Full Cone` / `Restricted Cone` / `Port Restricted Cone` —— 能打，继续。
  - `Symmetric`（对称 NAT）—— 成功率很低。这是协议层面的限制，不是配置问题，换什么工具都一样。可以打电话给运营商要公网 IP，或者改用有中转服务器的方案（frp、zerotier 这类）。
- **NAT 层数**：显示多层（运营商 NAT + 自己的路由器）时打洞会更难一些，但不是不行。

> 页面上还会显示 UPnP 有没有可用的网关。没有的话去路由器后台把 UPnP 打开——不开也能跑，只是端口映射要靠打洞自己维持，稳定性差一截。

---

## 1. 把服务加进来

「内网穿透」→「添加设备」。

**不知道 NAS 的内网 IP？** 别去路由器后台翻 DHCP 列表了，用「局域网扫描」：

1. 点「局域网扫描」，选一段网（一般就是 `192.168.1.0/24` 这种，本机在哪段会标出来）。
2. 扫完列出在线的机器和它们开着的端口。常见端口带名字——看到 `5000 群晖 DSM`、`5244 Alist`、`8096 Jellyfin` 就知道是什么了。
3. 点那个端口，IP、端口、服务名就带过去了，直接建服务。

手动加也行：设备名随便起，IP 填那台机器的内网 IP；然后在设备下「添加服务」，填服务名、内网端口、协议（网页服务选 TCP）。

**服务名起短一点、用英文**，后面 `/go/{服务名}` 要用到。

保存后回到列表，等几秒——状态会从「探测中」走到「已连通」，右边出现一个 `公网IP:端口` 的地址。**拿这个地址在手机流量下（不要连家里 WiFi）试着打开**，能打开就说明洞通了。

> 打不开的常见原因：那台机器自己的防火墙挡着；服务只监听了 `127.0.0.1` 没监听 `0.0.0.0`；NAS 上那个服务压根没开。先在局域网里用 `内网IP:端口` 试一下，局域网都不通就不是 LinkStar 的事。

---

## 2. 给它挂上证书

这一步不是可选的洁癖。很多服务（尤其是带登录的）在 `http://` 下会拒绝保存密码、拒绝用摄像头麦克风；而且你的密码是明文过公网的。

「证书管理」→「添加证书」→ 选 **ACME DNS-01**：

| 填什么 | 说明 |
| --- | --- |
| 名称 | 自己认得就行 |
| 域名 | `nas.example.com`，或者直接 `*.example.com` 一张管全部 |
| 服务商 | 选你域名所在的那家。**没有的话先去下一步配好 DDNS 服务商，这里会自动出现** |
| 邮箱 | Let's Encrypt 用来发到期提醒 |
| 环境 | **先留正式**。staging 签出来的证书浏览器不认，只用来调通流程 |

保存后等十几秒到一两分钟（要写 TXT 记录再等 DNS 生效）。签好了列表里会显示到期日和剩余天数，到期前会自动续，续的时候连接不断。

**为什么推荐 DNS-01 而不是 HTTP-01**：HTTP-01 要求公网 80 端口能进得来，而家宽 80 端口多半被运营商封了。DNS-01 不需要任何入站端口，还能签通配符。

> 只是内网自己用、不在乎浏览器报不报警，那就用**自签**——全新安装已经自带一张了，什么都不用做。浏览器会显示不安全，点「继续前往」能进去。

回到「内网穿透」，编辑刚才那个服务：

- **域名** 填 `nas.example.com`
- 勾上 **由 LinkStar 在洞口终结 TLS**
- **证书** 选「自动匹配」就行（按域名挑）
- **内网服务本身是 HTTPS** —— 看你的 NAS：DSM 默认 5000 是 http、5001 是 https。内网那段是明文就别勾，是 https（自签也算）才勾。这个勾只管内网这一段，和外面是不是 https 没关系。

---

## 3. 让域名跟着家宽 IP 走（DDNS）

家宽的公网 IP 一般一两天换一次，换了域名就指错地方了。

「DDNS」→ 先「添加服务商」：

- 类型选 Cloudflare（或你用的那家）
- Token 填进去

> Cloudflare 的 Token 在 **我的个人资料 → API 令牌 → 创建令牌**。权限至少要 `区域 - DNS - 编辑`，区域资源选上你的域名。注意是**令牌（Token）**，不是「全局 API 密钥（Global API Key）」，两者不通用。

再「添加记录」：

- 域名选你的，子域名填 `nas`
- 类型 `A`
- **IP 来源选 `stun`** —— 用打洞探到的公网 IP，和服务对外的地址是同一个
- Cloudflare 的 **proxied（橙云）关掉** —— 开了的话 Cloudflare 的代理不转发打洞出来的高位端口

保存后点「立即同步」，状态变绿就成了。之后每 5 分钟自动查一次，IP 变了就推上去。

现在 `https://nas.example.com:端口` 能打开了，浏览器也不报警了。

## 4. 让地址固定下来

还剩一个问题：**那个端口是会变的**。洞断了重开，端口就换一个，你存的书签就废了。

有两个办法，按需要选。

### 办法 A：入口重定向（Cloudflare 专属）

让一个固定域名 `linkstar.example.com` 始终自动跳到服务当前的真实地址。端口怎么变，这个域名都对。

编辑服务 →「入口重定向」→ 开启：

| 填什么 | 填成什么 |
| --- | --- |
| 服务商 | 选上一步配好的那个（Token 不用再贴一遍） |
| 入口域名 | `linkstar.example.com` —— 外面访问用的名字 |
| 落地域名 | `nas.example.com` —— 真正连过去的那个 |
| 保留路径 | 按需，一般开着 |

zone / ruleset / rule 三个 ID **都不用填**，后端自己查。

保存后界面上会摆出两条解析记录的现状，**照着核对一遍**，这两条的要求正好相反：

- **入口域名 `linkstar` 要开橙云** —— 不开的话请求根本不经过 Cloudflare，重定向规则轮不到执行。
- **落地域名 `nas` 要关橙云** —— 开了的话 Cloudflare 不转发高位端口。

> 配反了两边都不报错，只表现为「访问不了」。这是最容易卡住的一步，务必对着界面上那两行看一眼。

配好之后，外面记 `https://linkstar.example.com` 这一个地址就够了。

### 办法 B：服务索引（服务多了之后用这个）

办法 A 有个天花板：**Cloudflare 免费版的重定向规则上限是 10 条**，一个服务一条，加到第 11 个就没了。

服务索引换了个思路：**只把 LinkStar 自己这一个洞暴露出去，其余服务全部由它查表跳过去**，Cloudflare 规则从 N 条降到 1 条。

做法是给 LinkStar 自己（3333 端口）也建一个服务、打一个洞，然后只给它配入口重定向。之后：

```text
https://linkstar.example.com/nas        （Cloudflare，唯一一条规则）
  → https://ls.example.com:21313/nas    （LinkStar 自己的洞）
  → 307 https://nas.example.com:34521/  （nas 的洞）
```

外面访问 `https://linkstar.example.com/nas` 就到 NAS，`/jellyfin` 就到 Jellyfin，**新加服务不用再动 Cloudflare**。

写成 `/go/nas` 也行，效果一样——显式前缀是给服务名和前端路由、静态资源撞车时留的后路。服务名不区分大小写，后面的路径和参数原样带过去，`/nas/library/x` 会跳到 `.../library/x`。

洞还没打通、或者服务被停用时，给的是一个写明原因的页面，不是一个注定打不开的跳转。

> 两个办法不冲突，可以一起用：重要的服务单独给一条规则（地址更短），其余的走索引。

## 5.（可选）多个服务共用 443，用反向代理

到这里每个服务都占一个高位端口。服务多了之后记不住，而且有些公司网络只放行 80/443。

如果你**已经有公网 IP**（或者已经用某种方式把 443 打通了），可以用内建反向代理，按域名分流：

「反向代理」→ 先开「默认入口」：

- HTTP 端口 `80`、HTTPS 端口 `443`（首次安装这两个是预填好但没启用的，点开启才会真正占端口）
- 默认证书选「自动匹配」

再「添加站点」，一个站点对应 nginx 的一个 `server` 块：

| 填什么 | 说明 |
| --- | --- |
| 域名 | `nas.example.com`，可以填多个 |
| 后端 | `192.168.1.10:5000`，内网那台 |
| 后端走 HTTPS | 内网那一段是明文就别勾 |
| 对外 HTTPS | 勾上 |
| 证书 | 自动匹配 |

保存即生效，不用重启。WebSocket 和 SSE 是原样透传的，Jellyfin、Home Assistant 这类能正常用——`Host` 会写回客户端原本发来的那个，所以它们生成的跳转地址不会变成内网 IP。

后端连不上时会给一个写明「哪个站点、哪个后端」的 502 页面，比浏览器那句 `ERR_CONNECTION_REFUSED` 好查。

## 常见卡点

**地址栏敲「域名:端口」打不开，还标「不安全」**
浏览器对 `域名:端口` 默认按 http 发，而那个端口上等的是 https。现在会自动 302 到 https，直接就进去了。手动加上 `https://` 也行。

**界面显示「成功」，但入口域名打不开**
洞重开换了端口，而 Cloudflare 那边还是旧端口。这段空窗期界面会显示黄色的「外网端口已经换了」，洞确认通了会自己改过去，一般几十秒。等不及点「立即同步」。

**开机后域名指着旧地址**
公网 IP 一拿到就会自动触发同步，正常几十秒内跟上。超过五分钟还不对，去「DDNS」看那条记录的状态和错误信息，多半是 Token 权限不够。

**证书签不下来**
- 一直卡在验证中 → DNS TXT 记录没写进去，检查 Token 有没有 DNS 编辑权限。
- 提示被限流 → 正式环境一小时失败 5 次就会被挡住，等一小时，别反复试。
- 浏览器说证书无效 → 看看是不是签的 staging 环境，或者用的是自签。

**删了服务，DNS 记录还在**
正常情况会一起删掉。有三种情况故意不删：这条记录不是 LinkStar 自动加的、你自己改过它、还有别的服务在用同一个域名。
