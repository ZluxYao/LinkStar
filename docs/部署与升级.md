# 部署与升级

装成开机自启的常驻服务，以及升级、备份、迁移、卸载。

---

## 一条必须先知道的事

**LinkStar 把 `config/`、`data/`、`logs/` 建在「进程的工作目录」下，不是二进制所在的目录。**

手动双击或 `./linkstar` 跑，这两个正好是同一个，看不出区别。但交给 systemd 之后，工作目录默认是 `/`——配置会写到 `/config/`，而且下次你换个方式启动又找不着了，看起来就像「配置丢了」。

所以下面所有的服务配置里，**工作目录那一行是必填的，不是可选项**。

---

## Linux：systemd

### 1. 放文件

```bash
sudo mkdir -p /opt/linkstar
sudo cp linkstar /opt/linkstar/
sudo chmod +x /opt/linkstar/linkstar
```

架构对应关系见 [README 的下载表](../README.md#快速开始)。不确定自己是哪个架构：

```bash
uname -m
```

`x86_64` → `linkstar`；`aarch64` → `linkstar-linux-arm64`；`armv7l` → `linkstar-linux-armv7`；`mips`/`mipsel` → `linkstar-linux-mipsle`。拷过去之后都重命名成 `linkstar` 就行。

### 2. 写 service

```bash
sudo nano /etc/systemd/system/linkstar.service
```

```ini
[Unit]
Description=LinkStar
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/linkstar
ExecStart=/opt/linkstar/linkstar
Restart=on-failure
RestartSec=5s

# 退出时要保存配置，给够时间，别急着 SIGKILL
KillSignal=SIGTERM
TimeoutStopSec=30s

[Install]
WantedBy=multi-user.target
```

`After=network-online.target` 是有意义的：STUN 要向外发包，网卡还没拿到地址的话第一轮探测必然失败（虽然后面会自己重试）。

### 3. 起来

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now linkstar
sudo systemctl status linkstar
```

看日志：

```bash
sudo journalctl -u linkstar -f
```

也可以直接看 `/opt/linkstar/logs/YYYY-MM-DD/`，或者在管理后台的「运行日志」页面看，带级别和关键字过滤。

### 想用非 root 跑

默认 root 跑最省事。想降权的话：

```bash
sudo useradd -r -s /usr/sbin/nologin linkstar
sudo chown -R linkstar:linkstar /opt/linkstar
```

在 `[Service]` 里加：

```ini
User=linkstar
Group=linkstar
```

**这时要注意两件事**：

1. **反向代理的 80 / 443 绑不上了**——Linux 上非 root 进程不能监听 1024 以下的端口。要用默认入口就得再加一行：

   ```ini
   AmbientCapabilities=CAP_NET_BIND_SERVICE
   ```

2. **UPnP 和 STUN 不需要 root**，这部分不受影响。

### 防火墙

管理端口和打洞出来的端口都要放行。打洞端口是高位随机的，范围没法提前知道，所以一般是整段放行：

```bash
# ufw
sudo ufw allow 3333/tcp
sudo ufw allow 1024:65535/tcp
sudo ufw allow 1024:65535/udp

# firewalld
sudo firewall-cmd --permanent --add-port=3333/tcp
sudo firewall-cmd --permanent --add-port=1024-65535/tcp
sudo firewall-cmd --permanent --add-port=1024-65535/udp
sudo firewall-cmd --reload
```

> 觉得整段放行太宽的话，可以先不开，等服务跑起来看它实际拿到的端口再逐个放——代价是洞重开换了端口就得再改一次。

## OpenWrt：procd

空间紧张的话用 `linkstar-linux-mipsle`（或对应架构），放在**外挂存储**上，别放在只读的固件分区里。

`/etc/init.d/linkstar`：

```sh
#!/bin/sh /etc/rc.common

START=95
STOP=10
USE_PROCD=1

start_service() {
    procd_open_instance
    procd_set_param command /mnt/sda1/linkstar/linkstar
    procd_set_param env HOME=/mnt/sda1/linkstar
    procd_set_param cwd /mnt/sda1/linkstar
    procd_set_param respawn
    procd_set_param stdout 1
    procd_set_param stderr 1
    procd_close_instance
}
```

```sh
chmod +x /etc/init.d/linkstar
/etc/init.d/linkstar enable
/etc/init.d/linkstar start
```

`procd_set_param cwd` 就是上面说的工作目录，别漏。

> LinkStar 跑在路由器上有个额外好处：它本身就在网关位置，UPnP 那一跳省了。但路由器的 CPU 和内存通常很紧张，服务多了之后转发会成为瓶颈，跑几个轻量服务合适。

## Windows

### 桌面版（推荐个人用）

`linkstar-desktop.exe` 双击就行，有窗口有托盘，关掉窗口最小化到托盘。

开机自启：`Win + R` 输入 `shell:startup`，把 exe 的快捷方式丢进去。

### 命令行版装成服务

`linkstar-cli.exe` 适合放在常年开机的机器上。

**注意工作目录**——用任务计划程序的话，「起始于」那一栏必须填 exe 所在目录，填了才不会把配置写到 `C:\Windows\System32\`。

```powershell
# 开机启动、以 SYSTEM 身份跑、不弹窗
schtasks /create /tn "LinkStar" /sc onstart /ru SYSTEM /rl HIGHEST `
  /tr "cmd /c cd /d D:\LinkStar && D:\LinkStar\linkstar-cli.exe"
```

想要更像个正经服务（自动重启、日志重定向），用 [NSSM](https://nssm.cc/)：

```powershell
nssm install LinkStar D:\LinkStar\linkstar-cli.exe
nssm set LinkStar AppDirectory D:\LinkStar
nssm set LinkStar AppStopMethodConsole 20000
nssm start LinkStar
```

`AppStopMethodConsole` 是留给它保存配置的时间，别设太短。

Windows 防火墙第一次运行会弹窗询问，**勾上「专用网络」和「公用网络」都放行**，只勾专用的话外面进不来。

## 升级

配置文件格式是向后兼容的，**直接换二进制就行**，不用导出导入。

```bash
sudo systemctl stop linkstar
sudo cp linkstar /opt/linkstar/linkstar      # 覆盖
sudo chmod +x /opt/linkstar/linkstar
sudo systemctl start linkstar
```

Windows 同理：停掉服务 / 退出托盘 → 覆盖 exe → 再启动。

**升级前建议先备份一次 `config/`**，小成本保险：

```bash
sudo cp -r /opt/linkstar/config /opt/linkstar/config.bak.$(date +%F)
```

### 跨版本升级要留意的

每个版本的 [Release 说明](https://github.com/ZluxYao/LinkStar/releases) 里有「升级注意」一节，跨多个版本升的时候值得扫一眼。目前已知的：

- **0.53 / 0.5.4 → 0.6.5**：密码长度下限从 6 提到 8，只影响新设和改密码，老密码照常能登；改密码之后其他设备要重新登录。Cloudflare 规则名格式变了，下次同步会就地改名，不会多出重复规则。入口重定向开了两个以上的话，升级前服务商那边可能有几条是旧端口，换上新版重启第一轮心跳就全部重写，不用手工改。
- **反向代理从单端口升到双入口**：旧配置里那个端口会自动搬过去。原来是 https 的话，已有站点会被一起勾上 HTTPS——否则升级完站点会从 443 上消失。这一步是自动的，不用手工改。

### 回退

换回旧的二进制就行。但**新版本写过的配置文件，旧版本不一定认得全**——回退前把升级前备份的 `config/` 也换回去更稳妥。

## 备份与迁移

### 要备份什么

| 目录 | 要不要 | 说明 |
| --- | --- | --- |
| `config/` | **必须** | 所有配置。里面有 DNS 服务商 Token、管理密码哈希 |
| `data/cert/` | **建议** | 证书和私钥。不备份的话换机器之后 ACME 证书要重签（会撞限流） |
| `data/icon/`、`data/wallpaper/` | 看心情 | 图标和壁纸，丢了重传就是 |
| `logs/` | 不用 | 日志，每天一个目录，自己会长 |

```bash
sudo systemctl stop linkstar
sudo tar czf linkstar-backup-$(date +%F).tar.gz -C /opt/linkstar config data
sudo systemctl start linkstar
```

> **备份文件里有明文 API Token 和证书私钥**，别丢到公共网盘、别提交到 Git、别发群里。

### 换机器

1. 新机器上放好对应架构的二进制，按上面配好服务，**先不要启动**。
2. 把备份的 `config/` 和 `data/` 解压进工作目录。
3. 启动。密码、服务、证书、DDNS 全都在，不用重配。
4. 检查两处：
   - 「内网穿透」——设备的**内网 IP 可能变了**（换了网段、DHCP 重新分配），改成新的。
   - 「DDNS」——点一次「立即同步」，确认能推上去。

### 忘记密码

```bash
sudo systemctl stop linkstar
sudo rm /opt/linkstar/config/authConfig.json
sudo systemctl start linkstar
```

重启后回到设置密码的引导流程，其他配置不受影响。所有已登录设备会失效。

## 卸载

```bash
sudo systemctl disable --now linkstar
sudo rm /etc/systemd/system/linkstar.service
sudo systemctl daemon-reload
sudo rm -rf /opt/linkstar
```

**卸载之前先把服务在界面上删掉。** 直接删目录的话，DNS 服务商那边自动建的解析记录和 Cloudflare 规则会留着——它们会继续维护一个早就没有服务在听的域名，两头都不报错，以后查起来很费劲。在界面上删服务会把这些一起收走。

路由器上的 UPnP 映射也一样：正常退出会主动撤掉，`kill -9` 或者直接断电就留下了。留下的映射一般会随路由器重启消失，急的话去路由器后台手动删。

## 出问题先看这里

**服务起不来**

```bash
sudo systemctl status linkstar
sudo journalctl -u linkstar -n 50 --no-pager
```

最常见的是 **3333 端口被占**。看是谁占着：

```bash
sudo ss -lntp | grep 3333          # Linux
netstat -ano | findstr :3333       # Windows
```

3333 目前不支持改，只能把占着的那个程序挪开。

**配置好像丢了**
多半是工作目录不对，配置写到别处去了。`find / -name stunConfig.json 2>/dev/null` 找一下，然后把 `WorkingDirectory` 补上。

**改了配置文件没生效**
程序在内存里有一份，退出时会整个写回去——直接改文件会被覆盖掉。要手改的话先停程序，改完再启动。日常尽量在界面上改。

**洞总是断了重连**
看「运行日志」里那个服务的记录。常见原因：网关 UPnP 映射被别的设备顶掉了；运营商在做端口回收；那台机器休眠了。
